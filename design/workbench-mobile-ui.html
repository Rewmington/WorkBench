四版视觉，同一版式

版式已经定了（今天屏 A 清单 + 常驻输入条；课表屏 B 单日竖列）—— 这四版只比视觉语言，不比骨架

每版都是同样三屏（今天 / 课表 / 设置）+ 同一份演示数据 + 同步四态各一句。手机框按 360×800dp 画，正文 15px，触控目标 ≥48dp（PLAN §8.10 的基线，四版都达标，不达标会在下面那行实测里露出来）。每屏下面的实测行是浏览器量的，不是我估的：一屏能看到几条待办标题、内容溢出多少像素、最小触控目标多少像素。

能混着选，但色板只能选一套：①③ 用桌面已冻结的令牌（§8.5），② 只改密度不改色，④ 要新增三档 tonal 表面色阶 —— 那是桌面上不存在的一整套颜色，选了它就有两套令牌要维护。这条比字号重要，先想清楚。

固定四版都不许动的东西

骨架今天屏 = 清单 + 常驻输入条（A）；课表屏 = 单日竖列 + 7 日条（B）。已定，见 PLAN §8.10
分区顺序逾期 → 今天 → 随时 → 已完成。逾期独立成区、无截止时间的不混进今天
导航只有两项（今天 / 课表），设置从今天屏右上角齿轮进。不凑五项
文案「上次同步于 X · N 条待上传」类可验证的真事实；不出现「已同步」「同步中…」转圈；真空态与"还没同步过"是两句话
诚实状态不只靠颜色（§2 原则 3）：色块版每块仍带文字标签；「下一节」是描边 + 文字两个通道
数据课不进待办列表，只以空档摘要出现，且与课表页同一个函数算出来

差别四版各是什么主张

① 桌面直系② 松一点③ 色块分区④ 安卓原生味
一句话把桌面那套原样搬到手机上，一眼是同一个产品手机上不该塞桌面那么多字：去边框、放大行距、少一半元素状态用底色喊出来，扫一眼就知道哪条最急看起来像正经安卓 app，不像"套壳网页"
正文 / 行高15px / 54px16px / 62px15px / 56px15px / 58px
卡片与边框每条一个带描边的卡零边框，只有一条细分隔线描边 + 左侧色条 + 分区底色无边框，靠三档表面色分层
色板来源桌面 §8.5 原封桌面 §8.5 原封（只改密度）桌面 §8.5 + 复用已有的红/琥珀新增三档 tonal 表面，桌面没有
实现成本最低：令牌抄一遍低：改间距与边框，令牌不动中：分区底色与色条要写规则，暗亮两套都要校高：一整套新令牌 + 大标题收缩动效
主要代价手机上偏密、偏工程感一屏看到的条数最少颜色一多，"哪里最重要"反而可能糊与桌面越来越像两个产品

「一屏看到几条」这类数字我不写死在表里 —— 每版页面底部有浏览器实测行，翻到哪版看哪版。选法建议：先说色板要不要新增（④），再说密度要 ① 还是 ②，最后决定要不要 ③ 的分区底色。三问答完就定了。
