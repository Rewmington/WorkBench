## 2. 路线：为什么是 A

四条候选的完整取证在 [design/workbench-mobile.html](../design/workbench-mobile.html) ①（15 行决策表 + 来源清单），这里只留结论与出局理由。

| | 结论 |
|---|---|
| **A · Flutter + 坚果云中转** | ✅ **选它**。药箱已用这个模式跑通 PC↔Android 双端，传输层与合并规则都有现成先例 |
| B · PWA + 坚果云 | ✗ 国产 ROM 没有 GMS 就铸不出 WebAPK，"加到主屏"退化成浏览器书签；离线还得在坚果云之外再找一个公网 HTTPS 托管 |
| C · PWA + 局域网（PLAN 原设计） | ✗ **双重死锁**：私网 IP 不算 W3C secure context，Service Worker 装不上；而 Chrome 142 的 Local Network Access 权限又只发给 secure context 页面。两条规则互相把对方锁死 |
| D · Flutter + 局域网直连 | ✗ 技术成立（药箱 `lib/sync/lan_server.dart` 就是这么跑的，原生 app 发 HTTP 不需要安全上下文），但要求电脑开机且同一 Wi-Fi。**用户拍板：怕"电脑关着就同步不了" > 怕"数据出家门（密文）"** |

**退路**：A 在真机上被限流/验证堵死就退 D —— outbox、LWW、信封、两屏 UI 全部原样复用，只换传输层。这正是"先写数据层、后写传输层"的收益（§7 第 5 条）。

## 3. 同步模型

```
手机 Flutter ──HTTPS WebDAV──▶  坚果云 /dav/workbench-sync/  ◀──HTTPS WebDAV── PC (Rust)
        各设备只覆盖自己的 device-<id>.enc；读对方的文件，行级 LWW 合并进本地
```

### 3.1 权威副本：没有

`todos` 从此是**对等表**（药箱 `sync_service.dart:200` 的同款模型：合并完整表、发布自己那份，各设备只覆盖自己的文件）。

`classes` 例外，**单向 PC→手机**：手机对课表只读不写（桌面 §6.7 边界：导入即整学期替换，只发生在 PC）。所以冲突面只有 `todos` 一张表。

### 3.2 文件与一次同步的形状

- 目录 `/dav/workbench-sync/`，独立于 `workbench-backup/` 与 `medicine-sync/`（钉子见 §3.6）。
- 每设备一个文件 `device-<device_id>.enc` = **gzip 后的全量表 → 备份信封**（§4）。PC 那份含 `todos` + `classes`（含墓碑），手机那份只含 `todos`（含墓碑）。
- **快照的明文形状（M11a 定，M11c 补 meta，两端照这一份写）**：`{"ver":1,"device":"…","sealed_at":毫秒,"tables":{"todos":[行…],"classes":[行…]},"meta":{"timetable.term":"…","timetable.week1Monday":"…"}}`，一行是**列名→值**的 JSON 对象，键用 DB 的蛇形列名原样。选对象不选按位置的数组是因为两端版本不可能永远一致：数组错一位会静默把数据写歪，对象则看得见「对面没有这一列」。`dirty` 不在里面 —— 它是本机的「还没传出去」，传给对面只会让对面误判。实现与列清单都由 `PRAGMA table_info` 现取，不维护第二份列名字符串（`src-tauri/src/sync/snapshot.rs`、`mobile/lib/sync/snapshot.dart`）。
- **meta 是 M11c 补的缺口**：手机要用 `timetable.week1Monday` 算「今天第几周」、用 `timetable.term` 过滤旧学期，而 `settings` 表整体不同步（它是每台机器自己的 UX）。这两条不是偏好，是**解释 `classes` 表的基准** —— 少了它们，手机拿到课表也算不出这周上什么。所以快照加一个白名单 `meta`，只放这两条；PC 那份从 settings 取，手机收到后写进自己的 settings。旧快照没有这个对象，读成空表而不是「文件坏了」。
- 一次同步：`PROPFIND`(Depth:1) 列目录 → `GET` 对方文件 → 行级 LWW 合并 → **本地有写入（`dirty=1`）才** `PUT` 自己那份。首次多一个 `MKCOL`。
- 时机：**打开 app 时 + 手动按钮**，与药箱一致（`lib/app.dart:82`）。

### 3.3 四条规则，每条都是别人踩过的坑

1. **没有 `since` 游标，全量拉。** 药箱 `sync_service.dart:65` 把游标固定成 0，注释写明墙钟游标在对端时钟偏差下会**永久漏记录**（`:112`：「手机满勤、电脑一堆遗漏」）。待办量级几百到几千行，全量代价可忽略，`sync_cursor` 表因此不建。
2. **清脏标记比行自己的 `updated_at`，不比本机 now。** 药箱 `db.dart:246` 的教训：PUT 成功后只清 `updated_at <= 本次快照戳` 的行。序列化之后、响应回来之前新写的那条必须留在 outbox 里，否则会被下一次合并悄悄盖掉。
3. **整行替换，不做字段级合并。** 比较 `(updated_at, updated_by)`，`sync/lww.rs::is_newer` 已带设备 id 平票裁决 —— 那句"等真有对端要合并时再写"在这里兑现。实现落在 `sync/merge.rs`，用的是「有则 UPDATE 全列、无则 INSERT」而**不是 `INSERT OR REPLACE`**：REPLACE 先删后插，删的那一刻 `parent_id REFERENCES todos(id)` 会当场失败（本机外键是开着的），改父项就会炸子项。这一条有测试钉住（`a_child_row_survives_merging_its_parent_writing_that_way`）。合并进来的行 `dirty=0` —— 它已经在云上那份里了，不该再算本机欠账。
4. **墓碑永不清理。** 全量快照传播删除意味着：清掉墓碑后，任何一台旧设备的快照都会把已删的行复活。个人量级几千行墓碑不值当写一套回收逻辑。**这是路线 A 的固有代价，记下来而不是假装能优化。**

### 3.4 脏标记列（要写迁移）

桌面 §5.1 的五列同步字段里**没有 `dirty`**，药箱有。迁移 `0006_sync_dirty.sql` 给 `todos` 加 `dirty INTEGER NOT NULL DEFAULT 0`（`classes` 不加：手机只读它，PC 每次导入都是本地写入，整表随快照发布即可）。它承担两件事：

- 界面那句「N 条待上传」的计数来源（`count(*) where dirty=1`）；
- "本次没有本地写入就跳过 PUT"的省配额判断。

> **2026-10-31 补（课表触发）**：`classes` 没有 `dirty` 列（手机只读它），所以 PC 的「跳过 PUT」不能只数待办。最终判据是 **PC 只要本地有数据（todos/classes 任一行）就发布全量快照，只有真正的空库才跳过**。先试过「课表 `updated_at` 晚于上次同步才发」，但只拉取过的机器 `lastSyncAt` 可能晚于课表更新时间，仍会漏（真机复现：`workbench-sync` 只有空目录、没有 `device-pc-*.enc`）。PC 同步只在启动/手动发生，多传几十 KB 换确定性，比省配额重要。

> **M11a 落地补记**：列默认 0，但**存量行在迁移里一律置 1** —— 它们从没上过云，初始化成 0 就是谎报"已经传出去了"，而下一句"没有本地写入就跳过 PUT"会让它们永远留在家里。写路径共 9 处（`repos/todos.rs` 的 insert / update_row / soft_delete / restore / reorder / rebalance / take_due_reminders 与 `seed.rs` 的种子行）逐个 `dirty = 1`；漏一处不会报错，只会让那一行永远上不了云，所以有一条测试按「清脏 → 走一条写路径 → 数它脏了几行」的顺序把每条路径都过一遍（`every_local_write_path_marks_the_row_pending`）。`reminded_at = NULL` 那一处不单独置脏：它紧跟着 `update_row`，同一次调用里已经被置脏。

### 3.5 配额账（估算，不作验收依据）

假设 1000 条待办 + 30 行课表、明文 ~250KB、gzip ~30KB：每天开 app 10 次 × 2 端 × (GET+PUT 各 30KB) ≈ 1.2MB/天 ≈ **36MB/月**，上下行各远低于坚果云免费档 1GB 上 / 3GB 下；请求数 ~60/天，限流是 600 次/30 分钟，不触。

**真机跑一周后把实测值回填到这里。** 免费档另有单次 750 项、单文件 500M 的限制，个人量级远够不到。

### 3.6 三向目录钉子

写错目录不是小事，所以每个客户端在类型层钉死自己那一个，**不靠自觉**（照 `backup/webdav.rs:74-94` 与 `linking/dav_readonly.rs` 的现有做法）：

| 客户端 | 只许写 | 拒绝 |
|---|---|---|
| `backup::webdav::Remote` | `/workbench-backup/` | `medicine-sync`；文件名 `device-*`（现状不变） |
| `linking::dav_readonly::ReadRemote` | 只读 `/medicine-sync/` | `/workbench-backup/`；**补拒 `/workbench-sync/`** |
| `sync::relay::Remote`（M11b 新建） | `/workbench-sync/` | `medicine-sync`、`workbench-backup` |

另两条硬边界不变：**绝不写药箱的 `medicine-sync/`**，**不去读药箱存在它自己凭据管理器里的那把**。

### 3.7 药箱只读视图（M11e，2026-10-31 拍板）

用户平时**只用手机药箱记录并同步**，电脑上的药箱不用。所以手机端直接读药箱自己发布的那份，不经 PC：

```
药箱手机端 ──PUT──▶ 坚果云 /dav/medicine-sync/device-<药箱设备号>.json
Anvil 手机端 ──PROPFIND + GET（只读）──▶ 同一目录
```

- **只读在类型层，不靠自觉**：`sync/medicine_sync.dart` 的 `MedicineCloud` 只有 `PROPFIND` 与 `GET`，没有 `MKCOL/PUT/DELETE`；base 只认 `/medicine-sync/` 结尾，拒绝 `workbench-sync` / `workbench-backup`。测试断言桩侧收到的动词集合就是这两个。
- **不读同机药箱的本地库**：药箱的 SQLite 在它自己的 Android 沙箱里（`getApplicationSupportDirectory()`），Anvil 是另一个包，读不到；也不去读它存在 `shared_preferences.json` 的明文密码。
- **凭据复用 `Anvil/webdav`**：坚果云应用密码是账号级的，任一把都能读；手机上不新增密码条目，也不向 medicine-sync 写任何东西。
- **药箱账号可以与工作台不同**：`medicine.email` + Keystore 里的 `Anvil/medicine-webdav`；邮箱留空才回退到同步那组。应用密码是账号级的 —— 同一个坚果云账号换一把应用密码也能读，**不同账号必须单独填**。
- **合并规则照药箱**：同 id 取 `updated_at` 更新的行；平票取发布更晚的那份、再按设备号（只读视图必须与读取顺序无关）；墓碑行不显示；`published_at` 取各文件最大者。两张表：`medicines` / `dose_logs`。
- **新鲜度 = 药箱上次发布**，不是此刻：卡片写「药箱 12:03」，详情写「药箱发布于 12:03 · 读取于 12:05」。断网/401 时保留上一次的视图，并单独记一句「这次没读到」。
- **缓存**：合并后的视图落 settings `medicine.view`（本机、不上云）；失败不覆盖旧视图；开关关掉即停（不发请求、不画卡片）。

## 4. 凭据与加密：复用备份信封，不新造密码学

- **没有配对、没有二维码、没有 token。** 信任边界 = 坚果云账号 + 信封密钥。桌面原 §6.5 的局域网配对整套作废，`devices` 表不建 —— 设备清单就是远端目录里那几份 `device-*.enc` 的 listing。
- 信封**原样复用** `src-tauri/src/backup/crypto.rs`：`ANVILBKP | ver | kdf | m/t/p | salt[16] | nonce[12] | 密文`，Argon2id + AES-256-GCM，AAD 覆盖 nonce 之前的头部（kdf 参数或 salt 被换掉时认证标签直接不通过，而不是悄悄用错的钥匙解出乱码）。
- KDF secret 仍是 `邮箱:应用密码` —— **与备份同一把凭据**，不新增第三把密码。PC 侧在 Windows 凭据管理器 `Anvil/webdav` 条目；手机首次设置时手输同一组邮箱 + 应用密码，存 Android Keystore（`flutter_secure_storage`）。**不抄药箱把应用密码明文放 `shared_preferences.json` 的缺点。**
- 信封头部自带 KDF 参数、`open()` 会夹住上限（`crypto.rs:130-147`），所以**手机可以用比日备更低的 Argon2 成本**：64MiB/3 在桌面 ~120ms，真机耗时未知（§7 第 1 条）。若实测需要降，**下限 16MiB/3，降的是成本不是算法**，两端互通不受影响。
- **M11a 实测把这条定成了两档成本**（`mobile/test/argon2_bench_test.dart`，本机 Dart VM、纯 Dart 实现）：64MiB/3/1 单次 **632 ms**、16MiB/3/1 单次 **129 ms**、8MiB/3/1 62 ms。一次同步 = 自己 seal 一次 + 开对方一次 = 两次派生，日备那档在手机上就是 ~1.26 s 的白等，而 §7 第 1 条写的门槛正是 1 s。**所以同步信封走 16MiB/3/1**：Rust `crypto::seal_with(..., SYNC_M_KIB, ...)` 与 Dart `KdfParams.sync()` 同一档，日备仍是 64MiB（一天一次，不动）。参数写进头部，读哪份文件就用哪份的成本，所以**关键约束不是"两端参数相同"，而是"手机开 PC 那份时别被迫用 64MiB"** —— PC 发同步快照时也必须用同步那档。真机耗时仍然要回填（§7 第 1 条），但降不降参数的判断依据已经有了。**2026-10-31 Android 15（x86_64 模拟器）release/AOT 实测**（`ANVIL_BENCH=1`，48 KB 明文）：16 MiB 那档 seal 215 ms / open 87 ms → 一次同步 ≈ 302 ms；64 MiB 那档 ≈ 742 ms，两档往返都一致。**这是模拟器，不算实体机数据**；它只说明 16 MiB 的余量很大，实体机若明显更慢再按 §7 第 1 条处理。
- Dart 侧 Argon2 实现选型（libsodium FFI vs 纯 Dart）留到 M11a 实测定。**验收是跨语言测试向量**：Rust seal → Dart open、Dart seal → Rust open 各一条进测试。
- **"加密后才上传"必须可验证**（桌面 §8.9）：坚果云网页下载任一 `device-*.enc`，看到的就是 `ANVILBKP` 魔数开头的密文。不说"你的数据只属于你"。
- **M11c 落地**：手机侧 `credentials.dart` 的 `SecurePasswordVault` 只用 `flutter_secure_storage` 一个键（`Anvil/webdav`，与桌面凭据管理器同名的目标），邮箱进 settings、密码不进库；测试断言整张 settings 序列化后不含密码。**一个本机工具链的坑**：该包的 Windows 实现要 ATL（`atlstr.h`），而截图构建走 Windows，会把取证链挡死；所以 `mobile/third_party/flutter_secure_storage_windows` 是同一版本的本地副本，只删掉 C++ 插件、保留 Dart FFI 实现，Android 侧仍用主包的 Keystore 实现。这是**取证工具链的补丁，不是加密方案的改动**。

## 5. UI 定稿

### 5.1 视觉方向：桌面直系

2026-10-30 四版对比（[design/workbench-mobile-ui.html](../design/workbench-mobile-ui.html)，每版三屏 + 同步四态 + 浏览器实测行）后选定 **① 桌面直系**：桌面 §8.5 冻结令牌原样搬到手机上，**零新决策、零新令牌**。

| 选它的原因 | 接受的代价 |
|---|---|
| 色板、圆角、状态色全部与桌面同源，手机上"一眼是同一个产品" | 手机上偏密、偏工程感；桌面 13px 基线抬到 15px 后，同样的边框卡叠在一起会有点挤 |
| 实现最省：抄一遍令牌，不需要第二套色阶 | 分区底色（③）那种"状态用颜色喊"的直觉收益拿不到 —— 靠文字标签与位置表达状态（桌面 §2 原则 3） |

**被拒的三版留档在那份对比稿里**：② 松一点（零边框、16px/62px，代价是一屏看到的条数最少）、③ 色块分区（逾期整条铺红，代价是暗亮两套要逐屏校对比度）、④ 安卓原生味（Material 3 三档 tonal 表面 + 药丸导航，代价是**新增一整套桌面上不存在的色阶**，从此两套令牌要维护）。**④ 是这次唯一会破坏"令牌只有一套"的选项，不选它的理由就这一条，比观感重要。**

### 5.2 基线（同一套令牌在另一种设备上的另一组基线，不是改令牌）

设计框 **360×800dp**；正文 **15px**（桌面 13px 在手机上不适用）；触控目标 **≥48dp**；数字 `tabular-nums`；底部导航 54px、**只有两项：今天 / 课表**（超级课程表把查课表养成 86MB 平台的教训），**设置从今天屏右上角齿轮进**，不加第三个 tab。

### 5.3 今天屏 = 候选 A（清单 + 常驻输入条）

- 头部：日期 + 周次 + 三 KPI（逾期 / 今天 / 已完成）+ 右上齿轮（48dp）；其下一行同步状态；再下一行空档摘要「今天 N 节课 · 最近的空档 HH:MM–HH:MM」。
- 分区顺序 **逾期 → 今天 → 随时 → 已完成**，一条一行（实测行高 54px）。逾期独立成区、无截止时间的落「随时」不混进今天 —— 与桌面 §8.8 第 8 条同一条规则。
- **课不进这个列表**，只以空档摘要出现，且空档与课表页由**同一个函数**算（桌面 §8.8 第 7 条的硬约束照搬）。
- 勾选 = **延迟消失 + 撤销条**（Todoist 同款；窄屏上划线常驻最容易连点误触）。**撤销条必须让到输入条上面**（对比稿实测它会盖住输入条）。
- **用药卡**（M11e）在空档摘要下、待办区上，只在有药且开关开着时出现，不占 tab：
  - 第一行「用药」+ 右侧「药箱 12:03」（药箱自己的发布时间，不是 Anvil 读取时间）；
  - 第二行「今天 2/4 次」+ 右侧状态：待记（琥珀）→ 下一次 HH:MM · 药名 → 今天都记了；
  - 第三行只在需要时说库存：「已用完：X」（红）与「Y 剩 N 天」（琥珀）**分开着色**，一句话全红会夸大次要那条。
  - 点开是只读详情：来源时间、每种药今天的每格状态（已服 / 待记 / 未到 / 没吃）、余量与用量，底部一句「这里只读；回药箱打卡并同步后才会更新」。没有打卡按钮 —— 按下去能写药箱的按钮，这个 app 永远不会画。
- 已知代价（实测，接受）：800dp 高下演示数据 7 条标题溢出 319px、首屏只露 6 条 → 靠滚动，**不缩字号**。用药卡出现时首屏待办条数会再少一条（卡片约 74dp），同样是滚动，不缩字号。

### 5.4 课表屏 = 候选 B（单日竖列）

- 顶栏：周次 + 「左右滑切天」+ 左右按钮（48dp）+ **7 日条**（每格实测 48.6dp：满出血、缝隙 2px —— 360dp 宽下不收缝隙就只有 45dp，达不到 Android 最小触控）。有课的日子一个蓝点，跨月日期标"月"。
- 单日按大节竖排：左列起止时间，右侧**课名全文** + 教室·教师·周次。**空档显式写「空闲」**（桌面 §8.8 第 7 条同一条：这张表最有用的一件事是找空档）。
- 「下一节」= 描边 + 文字两个通道（§2 原则 3）。**注意是"下一节"不是"此刻"**：课间空档里没有"正在上的课"，对比稿第一版在这里说过谎。
- 底部空档摘要行与今天屏同值同函数。
- **已知偏离（用户已知并接受）**：竞品事实标准是压缩周网格（WakeUp 手机主界面就是 7 列，单日只做桌面小部件），选 B 是为了**课名全文可读**，代价是"这周哪几天空"要滑 7 次拼出来，而周网格一眼就有。这条不再争论；将来真想要周网格，按对比稿 ④ A 加视图，**不动数据层**。

### 5.5 同步怎么说（四条路都适用的文案纪律）

主屏状态行只写**可验证的真事实**：

| 留 | 为什么能留 |
|---|---|
| 「上次同步于 12:03 · 2 条待上传」 | 两个数都可验证：时间来自最后一次成功同步，条数来自 `dirty=1`。这是整页的核心 |
| 「没连上坚果云 · 显示的是 12:03 那份」 | 离线态不伪装实时，明说手上这份旧到什么时候 |
| 行末一个小黄点 = 这条还没传出去 | 行级而不是全局；用户勾选一条、黄点消失就是"这条出去了" |
| 「今天没有待办 —— 上次同步于 12:03」 | 真空态必须带同步时间，否则和"没同步到"长得一样（To Do 小组件翻车的地方） |
| 「还没同步过 · 这里可能是空的」 | 与上一句是**两种状态两句话**，不能共用 |

| 删 | 为什么谎 |
|---|---|
| 「已同步」 | 没有时间、没有条数、无法验证，而且下一次写入之后它立刻变成谎话 |
| 「同步中…（转圈）」 | 原生软件从不转圈；一条 PUT 可能要几秒，转圈会让用户以为卡死 |
| 「你的数据只属于你」 | 没有信息量，而且做不到绝对（坚果云上有密文） |

机制说明（手机能改什么、冲突谁赢、什么不上云）收进手机设置页「关于与隐私」，**主屏每屏最多一句 ≤20 字操作提示**（桌面 §8.9 三类话纪律照搬）。**但有一条必须在主屏**：走局域网时"电脑没开 / 不在同一 Wi-Fi"这类决定"现在能不能指望同步"的事实 —— 那是操作提示，不是机制说明。

## 7. 真机验证清单（M11 第一天，验不过的退路写明）

1. **Argon2id 在那台手机上的耗时。** 每次同步 = 自己 seal 一次 + 开对方文件一次，共两次派生。纯 Dart 实现 64MiB 可能是秒级 → 不可接受；libsodium FFI 预期百毫秒级。**实测 > 1s 就降参数（下限 16MiB/3）或换 FFI 实现**，信封头部带参数所以两端互通不受影响。
   > **M11a 进度**：选型已经不用等真机 —— 纯 Dart（`package:cryptography` 2.9）在桌面就把 64MiB 跑进 0.63 s，所以**不引 FFI**；同步那档降到 16MiB/3/1（单次 129 ms，见 §4）。真机要验的换成一句话：**这台手机上的 16MiB 那档两次派生加起来是多少毫秒**，实测回填 §4。若手机上连 16MiB 都要 1 s 以上，再谈 FFI（届时的判断依据写在这条下面，别凭印象改）。
   > **M11c 进度**：Android 15 x86_64 模拟器 release/AOT 实测 16MiB 一次同步 ≈ 302 ms、64MiB ≈ 742 ms（详见 §4）。实体机数值仍待 M11d。
2. **坚果云 WebDAV 从 Android 发得出去吗。** 药箱已验证过这条路，但那是它的账号与网络环境；本机要复跑 MKCOL / PROPFIND / GET / PUT 各一次。已知坑：PROPFIND 403 与微信二次验证（坚果云帮助中心有专页），撞上了就在设置页说人话，**不静默重试到死**。
   > **M11c 进度**：客户端与四个动词已实现，对着进程内 WebDAV 桩跑通（含 401、断网、`pending==0` 跳过 PUT）；真坚果云账号往返仍属 M11d。
3. **合并与墓碑的真机往返，四条**：手机新建 → PC 下次同步可见且 `rev` 递增；PC 勾选 → 手机可见；手机删除 → PC 消失且**再同步不复活**；两端同时改同一条 → 平票按设备 id 裁决，**结果两端一致**。每条一个自动化用例 + 真机各跑一遍。
   > **M11c 进度**：手机侧三条（拉取合并、上传、平票）已有自动化用例；Rust 侧同一批规则全绿，且有一条 Dart→Rust 的冻结快照向量。删除传播由两端的墓碑用例共同钉住；真机四跑仍属 M11d。
4. **侧载政策（盯，不阻塞）**：2026-09-30 起部分地区要求开发者验证（免费"有限分发" ≤ 20 台），2027 推向全球。自己装一台目前不受影响；真撞上就注册免费开发者账号，不为它改架构。
5. **退路**：若坚果云这条路被限流/验证堵死 → 退 **D（Flutter + 局域网直连）**，只换传输层。届时第一天要验的假设换成：Android 17（API 37）起默认拦局域网，授予 `ACCESS_LOCAL_NETWORK` 后纯 HTTP 能否连到 PC 端口。
6. **药箱只读视图的真账号往返**（M11e）：用平时记录手机药箱的那组账号，在 Anvil 设置里填一次，看卡片上的「今天 N/M 次」与药箱 App 的今日页是否一致；再在药箱里记一次、同步，回 Anvil 手动读一次，看是否更新；断网时看是否保留旧视图并说「这次没读到」。四条各记一张截图。
