# 威胁模型：这套软件防的是什么

> 写这一页的原因很实际：issue #1 那份审计里 6 条误报、8 条例子错，其中一大半不是因为读码的人眼神差，
> 而是因为**「这台软件防谁」从没写下来过**。没写下来，别人只能按通用口径审，你只能逐条解释「这是故意的」。

## 一句话

**这是一个人用的软件：威胁模型是「防手滑、防意外、防数据丢失」，不是「防攻击者」。**
任何要求我们防住外部输入的结论，都得先问：这条路径上真会出现别人的输入吗？

## 信任边界

| 边界 | 另一侧是谁 | 假设 | 因此怎么防 |
| --- | --- | --- | --- |
| 笔记正文 / Markdown | 只有我自己 | 恶意内容只可能来自手误或粘贴的网页 | DOMPurify + `SAFE_URI` 防的是"粘贴进来的东西在我窗口里执行脚本"；`open_url` 在 Rust 侧只放行 http/https/mailto/ftp，因为**点击不可撤回**，而 `//host/share` 会被 ShellExecute 当 UNC 路径拿凭据去访问 |
| WebDAV 对端的 `device-*.enc` | 我自己的其他设备 | 文件可能被我改坏、被旧版本写过、被截断，但不是对手构造的 | 解不开就跳过并点名（不中止整轮）；信封把 KDF 参数放进 AAD，参数被换能发现。**不做**防构造输入的加固：畸形 `%` 只保证不 panic，不保证解析得对 |
| 坚果云三个目录 | 同一个账号（应用密码是账号级的） | 分目录是为了**不出事**，不是权限隔离——任何一条密码都能访问整个账号 | 类型层拒绝：`linking::dav_readonly` 只有 PROPFIND/GET；读侧 `check_dir` 按路径分段拒绝 `workbench-backup`/`workbench-sync`，写侧 `webdav::Remote::new` 用 `ends_with` 正向白名单。**别把这三条目录当安全边界用** |
| 手机本地库 `anvil.db` | 拿到这台手机的人 | 手机丢失/被 root 是**真实风险**（课表、待办、用药记录都算个人数据） | 已关系统备份与换机迁移（`allowBackup="false"` + `fullBackupContent` + `data_extraction_rules.xml`）；云端那一份是加密信封。**本地库仍是明文**，见下 |
| 发布产物 | 装包的用户 | 供应链不在模型内；但"装了不能覆盖升级"是我们的错，不是用户的 | 缺签名 secrets 时 tag 构建直接 `exit 1`（`.github/workflows/release.yml`），不静默发 debug 签名的包 |

## 明说「不在模型内」的（审计问到过的，都归到这里）

- **gzip 炸弹的绝对上限**：压缩侧 32 MiB、解压侧 64 MiB / 还原库 512 MiB —— 目的是**不让手滑把内存吃光**，不是抵御故意构造的炸弹。真按攻击者口径，这几条都得重做。
- **凭据管理器不可用**（服务被锁、访问被拒）：报成读失败而不是"还没填"（`creds::take`），但没有额外的恢复向导。
- **多用户 / 不可信第三方设备**：不存在这个场景。同步目录里的对端只可能是我自己的设备。
- **时钟正确性**：LWW 只比墙钟，本机加了单调下限（`time::FLOOR_MS`）防止自己覆盖自己；**跨设备偏移没有解**，除非引入向量时钟。

## 已经定过的一条口径：手机本地库不加密

**2026-11-02 由作者拍板搁置**（此前是"唯一一条还没定的"）。现在的口径是：明文留在本机，但**不允许它经由系统备份离开设备**（`allowBackup="false"` + `fullBackupContent="false"` + `data_extraction_rules.xml` 三处都在）。

不换成 `sqflite_sqlcipher` 的理由，按大小排：

1. **换不来"恢复后还能读"**。密钥只能放 Keystore，从备份恢复后照样解不开 —— 明文库至少还能救数据，加密库直接变成砖。
2. 迁移本身是新风险：首次启动要把已有 `anvil.db` 迁成加密库，而这一轮刚在真机上验过"库打不开"会让人想卸载重装（批次 8 的 N16）—— 迁坏了正好撞上那个。
3. 药箱那边（`Rewmington/medicine`）同样是明文库，口径会不一致，以后还会被报"一半加密一半不加密"。
4. 原生依赖与包体积。

要重新考虑，先想清楚迁移路径和"恢复后读不了怎么办"，再动 `mobile/lib/db.dart`。**别再把它当未决项写进审计报告。**
