# 个人工作台 · 产品与工程计划

> 状态：v1 范围与架构已定，UI 方向待定（见 §8）。参考项目 x-hub v0.9.4（Tauri2+Vue3+Rust，约 11 万行，MIT）。

## 1. 定位

本地优先的个人效率工作台，Windows 桌面单机为主（手机伴侣延后到 v2）。打开即继续工作，一件事三步内完成。

与 x-hub 的三处差异化：

1. **与本机已有程序、已有云端联动是一等公民**，不是附加功能：v1 就接博客仓库 JSON、药箱 SQLite、坚果云备份（x-hub 完全没有外部数据源这一层：grep `手机/二维码/局域网/sync` 零命中）。手机伴侣原本挂着"第一差异化"的名号，2026-10-28 决定先做电脑端，降到 v2 —— 差异化的落点从"能连手机"变成"能接你已经在用的东西"。
2. **视觉层级**：x-hub 所有卡片同权重、暗色下卡与底几乎糊在一起。我们用两档表面 + 内容自适应，让眼睛有落点。
3. **范围克制**：不做扩展市场、Agent 工具编排、悬浮球、自更新链路。这些占掉 x-hub 一半代码量，却与"个人工作台"无关。

## 2. 设计原则

1. 下一步行动比信息浏览更快 —— 一切操作可从命令面板直达。
2. 空的不占地方 —— 无数据部件折叠成一行，不出现死白大块。
3. 状态不只靠颜色 —— 同时改变字重、位置、图标。
4. 数据位置可感知 —— 明确告诉用户库文件在哪、备份包含什么、手机连上来能做什么。
5. 联动诚实 —— 不在同一网络就是不能同步，不伪装"已同步"。

## 5. 数据模型

### 5.0 命名与落盘（一次定死）

产品名 **Anvil**。名字分三层，只有第一层不能改：

| 用途 | 值 | 可改性 |
|---|---|---|
| Tauri `identifier` | `dev.rewmington.anvil` | **不可改** —— 它决定数据目录与 AppUserModelID，改一次要写迁移脚本搬库 |
| 窗口标题 / 托盘 tooltip | `Anvil · 工作台` | 随时改 |
| mDNS 服务名（v2 手机） | `anvil.local` | 随时改 |
| 可执行文件 | `anvil.exe` | 跟 identifier 走 |

**数据库落 `%LOCALAPPDATA%\dev.rewmington.anvil\`，不要用 Tauri 默认的 `appDataDir`（那是 Roaming 目录）。** 两个真实风险：Roaming 目录在域控环境下随登录漫游，WAL 文件在漫游复制中途被读就是损坏；更常见的是有人把 `%APPDATA%` 放进了 OneDrive 同步范围，**SQLite + 云同步盘是经典损坏路径**。日志与图标缓存同目录，备份快照单独放 `…\backups\` 以便整体排除。这三个路径要在设置页原样显示出来 —— §2 原则 4「数据位置可感知」的落地就是让人看见绝对路径，不是看见"已加密"三个字。

反写域名 identifier 这个约定不是新发明，你的药箱就是 `%APPDATA%\dev.mine.medicine_tracker\`，照抄一致性。

**本机仓库目录名不属于以上任何一层，保持 `…\Mine\workbench` 不动。** 它不出现在窗口标题、数据目录、可执行文件名或远端目录里，改名没有任何一致性收益；而 Qoder 的项目身份与项目记忆目录都由工作区路径派生，改名等于新开一个项目、既有项目记忆不跟随。将来真要改的正确顺序：关闭会话 → 改目录名 → 重新打开（会生成新项目条目）→ 把旧 `projects\<旧键>\memory` 迁到新键下。

### 5.1 同步友好约定（所有可变更表必须遵守）

```
id          TEXT PRIMARY KEY     -- UUIDv7（时间有序，避免索引页分裂）
rev         INTEGER NOT NULL     -- 每次写入 +1
created_at  INTEGER NOT NULL     -- 毫秒时间戳；UUIDv7 前 48 位可推出，但显式存下便于查询
created_by  TEXT    NOT NULL     -- 建条目的设备 ID（统计的"来源"维度依赖它）
updated_at  INTEGER NOT NULL     -- 毫秒时间戳（写入设备的墙钟）
updated_by  TEXT    NOT NULL     -- 设备 ID，用于 LWW 平票裁决
deleted_at  INTEGER              -- 软删墓碑，同步靠它传播删除
```

`todos` 另有 `done_at INTEGER`：**取消勾选时不清空**，只递增 `rev` 并保留最后完成时间 —— 清空会让历史统计少一格。

> **2026-10-29 实施修正（M5a）**：上面这一句把两件事塞进了一个列 —— `done_at` 既当"最后一次完成于何时"（要留住），又被界面当"当前是不是完成态"用（要能撤销）。结果 `set_done(false)` 只推 rev，**勾选框只能完成、永远取消不了**，而该条目同时从"待办"和"已完成"两个视图里消失/留下。修法不是改 `done_at` 的语义（§5.1 的意图完整保留），而是加一列 `completed` 表达当前状态（迁移 `0002_done_state.sql`）。**统计口径统一只看 `completed = 1`**，于是"今天完成 N 件"永远等于已完成列表里的条数；`done_at`/`done_day` 退纯为"最后一次完成发生在何时"，供详情面板写"上次完成于 X"。

冲突解决：**行级 Last-Write-Wins**，比较 `(updated_at, updated_by)`。不引入 CRDT —— 两台设备、编辑面基本不相交，CRDT 的成本远大于收益。长文本（便签/笔记）规则：**手机只做追加与勾选，不做段落级并发改写**，从源头规避合并问题。

## 6. 联动

> **v1 只做 §6.1 与 §6.2**（三条只读数据源 + 坚果云备份）。§6.3 起的手机伴侣全套设计**保留但延后到 v2** —— 2026-10-28 决定先做电脑端。`todos` 的 `rev / created_by / updated_by / deleted_at` 同步字段**照旧保留**：现在留手是几行 DDL，v2 要补就得写迁移并面对"历史来源未知"。

### 6.1 v1：本机程序联动（只读）

| 源 | 接入方式 | 联网依赖 | 拿不到时 |
|---|---|---|---|
| 博客 `Rewmington-Blog-main` | 读仓库 `src/content/*.json`；有网时 GET `wmddd.online/content/*.json` 比对是否落后 | 无（线上只是校验） | 用 SQLite 缓存 + 显示"最后成功于 X 分钟前"；仓库目录被移动则部件折叠成一行虚线条，不弹错 |
| 药箱 `medicine` | 复制 `%APPDATA%\dev.mine\medicine_tracker\medicine_tracker.db` → 只读打开（它的 `tools/export_backup.dart` 就是这个套路）。**备用源**：配了第二条应用密码时再读一份它自己在 `/dav/medicine-sync/` 上的 `device-*.json` 全量快照，**谁的行更新用谁**，用了哪份写在界面上（见 §6.2 末） | 备用源要联网，没配就没这条 | 同上；副本读失败不生成任何待办 |
| 坚果云 | 每日快照 PUT / 需要时 GET 还原 | 仅备份与换机恢复 | 本地照常读写，下次 tick 重试并提示 |

三条共同点：**外部数据永远只进缓存表，不与 `todos` 同库同表**，所以外部程序升级或删掉都不会伤到工作台本体。

### 6.2 v1：坚果云备份与恢复

复用你在药箱里已经跑通的传输层（`dav.jianguoyun.com` + 应用密码 + Basic Auth），但**目录必须独立**：`/dav/workbench-backup/`。

不能共用 `/dav/medicine-sync/` 的原因是硬技术约束，不是洁癖：药箱 PROPFIND 时按 `device-` 前缀无差别挑文件并合并进本地，工作台一旦往那儿写，就会被当成一台设备，把博客/待办数据混进用药记录里。

凭据边界：药箱把应用密码明文放在 `shared_preferences.json` —— 这个缺点不抄，也**不去偷读它的凭据文件**；工作台要你在设置里自己填一次，之后交 Windows 凭据管理器，`resources.secret_note` 同样本机加密落盘。快照本身 AES-GCM 加密后再上传，坚果云只看到密文。

#### 读药箱的云端快照（2026-10-29 补）

要读云端那份 `device-*.json` 就得再要一次凭据，而**不去读药箱存在它自己凭据管理器里的那把**（同上一条边界）。于是有两把应用密码，各在凭据管理器一个条目下：`Anvil/webdav`（备份，可写自己的目录）与 `Anvil/medicine-webdav`（读药箱，只读）。

把两把的用处说清楚，别夸：**坚果云的应用密码是账号级的**，两把都能读写整个网盘，所以分开**不构成权限隔离**。它换来的是另外两件事 —— 可以在坚果云里单独吊销「读药箱」这一把而不停掉备份，以及从条目名称就知道这条授权是谁在用。真正的写入边界不靠凭据，靠类型：`linking::dav_readonly::ReadRemote` 只有 PROPFIND 与 GET，压根没有 PUT / MKCOL / DELETE 方法，编译期就写不了。反向钉子同样在：这个客户端拒绝任何指向 `/workbench-backup/` 的地址，备份那边也不列 `device-*`。

取哪一份只看行的 `updated_at`：云端更新才算云端赢，**平票算本机**（那是用户眼前的 app 刚写的）。用了哪份、对方发布于多久以前必须显示在页面上——云端那份可能是几小时前的快照，不写就是拿旧数据冒充实时（§2 原则 5）。云端读失败从不往上抛错，只把原因写进那一行：药箱被卸载、断网、凭据被拒，工作台照常可用。

### 6.3 v2（延后）：手机伴侣拓扑

PC 是唯一权威写入端（single-writer + 客户端提交变更）。手机是伴侣，不是对等节点。

```
手机 PWA  ──HTTPS/WSS──▶  PC (Tauri 内置 axum/hyper 服务)  ──▶  SQLite
                              ▲
                              └ 变更通过 WebSocket 推给手机，手机 UI 实时刷新
```

### 6.4 协议（最小面）

- `GET  /api/snapshot?since=<seq>` → `{ changes: [{entity, rows[]}], cursor }`，按全局变更序号增量下发
- `POST /api/apply` → 手机提交的变更集 `{ mutations: [{entity, id, data|null, rev, updated_at}] }`，PC 校验 rev 后落库并广播
- `GET  /api/launch/:id` → 远程触发速达启动（PC 侧动作，不返回数据）
- `WS   /api/events` → PC 推送 `changed` / `ping`
- 所有响应带 `Cache-Control: no-store`

### 6.5 配对与安全（v2）

1. PC 端「连接手机」生成二维码，内含 `https://<lan-host>:<port>/#pair=<一次性码>`。
2. 手机扫码打开，输入 6 位配对码 + 设备名。
3. PC 端弹窗确认 → 签发 256-bit 随机 token，手机存 localStorage，PC 只存 **SHA-256 哈希**。
4. 后续请求 `Authorization: Bearer <token>`；PC 端设备列表可逐个吊销。
5. 服务默认**关闭**，设置里显式开启并显示当前监听地址；首次开启写 Windows 防火墙规则（仅私有网络，需 UAC 确认）。

### 6.6 已知风险（v2 第一天就要验证）

- **Service Worker 需要安全上下文**：纯 `http://` 下 PWA 无法注册 SW，"添加到主屏 + 离线"就落空。方案：PC 端内置本地 CA 签发证书（mkcert 等价实现），提供根证书下载与手机安装引导。iOS 需用户在"描述文件"里手动信任，这一步**必须先拿真机验证**，验证不过则退化为"在线网页快捷方式"（可用，但无离线）。
- **手机不在同一网络时不可用**：v1 明确不做内网穿透，UI 上直说，不做假同步状态。
- **休眠/换 IP**：mDNS 服务名（`anvil.local`）+ 断线自动重连；失败时手机端保留最后一次快照并标注时间。

### 6.7 课表（教务导出 → 本机，2026-10-30 加）

**它是什么**：教务系统那张「星期 × 节次」矩阵在本机的一份副本。导入一次管一学期；调课就重导一次。

**三条边界（都不协商）**

1. **不碰教务网站**。不存教务账号密码、不爬页面 —— `jw.educationgroup.cn` 只是"这份文件从哪来"的说明，不是运行时依赖。断网、网站改版、放假停机，课表照常显示。这条与 §6.2「不去读别的程序存的凭据」是同一类：能不持有秘密就不持有。
2. **课不是待办**。`classes` 自己一张表，`todos` 里一行都不写。理由：上完一节课不是"做完一件事"，混进完成数会把统计页灌满（2026-10-30 定的口径）。待办可以**挂在课上**（点格子时右栏显示"这门课关联的待办"），但那是查询时的关联，不是数据耦合。
3. **导入即整学期替换**，按 `term` 划界：换学期导入不动上一学期的数据，同一学期重导不会越导越多。

**数据形状是从真文件倒推出来的，不是设计出来的**：导出是矩阵 —— 列 = 星期一…星期日，行 = `第N大节 / HH:MM-HH:MM`，格子里**五段一组** `课程名 / 教师 / 周次 / 教室 / 节次`，且**一个格子可以装两组**（同一门课的不同周次段可以在不同教室）。所以 `classes` 一行 = 一个「星期 × 节次 × 周次集合」，**不是一门课**；一门课在库里天然可能是好几行，界面按名字归组。

**编码只接 UTF-8**：中文 Windows 上 Excel 的「CSV(逗号分隔)」写的是 GBK。判出来不是 UTF-8 就明说「请改选 CSV UTF-8(逗号分隔)」，**不引解码依赖** —— 一个每学期一次的动作不值当拉一个库进来，而且限制看得见比隐形好。

**开学日是必填的第二件事**：CSV 里有"学年学期"，**没有"第 1 周是哪天"**。没它就算不出"今天第几周"，硬猜会猜错一整个学期。所以导入报告带 `needsWeek1`，课表页顶部要求填一次第 1 周的周一；学期总周数从各课周次集合的最大值推出来当默认值，可改。

**格子形状不对就拒绝导入**：段数不是 5 的倍数、或第 3 段不是周次 → 报错并指名是哪个格子。错位着导入会把教师存成教室，那种脏数据比"导不进去"糟得多。

**进不进备份**：进。它是手工导入并手工补了开学日的本机数据，丢了要重导 —— 与药箱/博客缓存（外部程序的只读副本，不进备份，§6.2）不是一类东西。

**v1 不做**：调课 / 停课例外表（导入即真相）、多学期并存管理、自动拉取。

### 6.8 博客源反过来：线上那份才是「我所有的项目」（2026-10-30 加，M10b）

你指出的两件事合起来是一条设计错误：**本地仓库不是权威源**。项目清单是 GitHub Actions 每天 cron 从 GitHub 重生成再部署的，本地 checkout 不会同步 —— 于是工作台显示的是"我很久以前拉下来的那份"。而 M3 当时的取舍（读本地文件、线上只用来打「落后」标签）恰好把优先级摆反了。

改后的规则，一句话：**线上赢，本机兜底，读的是哪一份必须写在脸上。**

- 抓取顺序：先 `https://wmddd.online/content/<kind>.json`（`blog_online::fetch_normalized` 已有），成功即作为这份快照的内容；失败（离线 / 冷启超时 / 改版）才退回 `<仓库>/src/content/<file>`，并在源那一行说明为什么用的是旧的。
- 源标注与药箱同一套路（`detail` 里写「线上 · 抓于 12:03」/「本机仓库 · 线上这次没够到：<原因>」），界面照抄，不自造"已同步"这种词 —— §2 原则 5：我们没往站点写任何东西。
- **`linked_check_online` 这条命令删掉**。它做的事（去线上看一眼）现在就是读取路径本身，留两个入口迟早出现「刷新出来和比对出来不一样」。设置页那个「比对线上」开关一并删。
- 风险与对策：站点冷启实测首包 ~8 s，7 个清单串行最坏 84 s。所以 ① 界面**先渲染缓存**，线上抓完再刷新（渐进，不空屏转圈）；② 7 个 GET 用 `std::thread::scope` 并发，每个仍是 12 s 预算，整体 ~12 s；③ 抓失败进抑制窗口，别每次进这一页都重撞一次冷启。

**别人的仓库结构不同就看不了 —— 这是事实，不当 bug 修**：这份契约（`content/projects.json` 等七个清单 + 各自形状）就是本站的形状。要通用得做字段映射，v1 没有第二个用户，映射界面是给不存在的人做的表单。所以只做一件事：**读不到时说明缺什么**（「这个源没有 `content/projects.json`，工作台认的是本站那套清单」），而不是给一张空卡片或一句「0 条」。

**已知阻塞（M10b 落地当天发现，未解）**：`https://wmddd.online` 在 Cloudflare 后面，证书由 **Google Trust Services WE1** 签发、链到 **GTS Root R4**，末端是**已过期的 GlobalSign Root CA 交叉签**。Windows 受信任根存储里没有 GTS 的根（Google 从未送进 Microsoft 的存储），浏览器自带根程序所以打得开，走 Schannel 的 `native-tls` 打不开 —— 实测报 `native-tls: unable to find any user-specified roots in the final cert chain`。对照 `dav.jianguoyun.com`（Sectigo → USERTrust，都在存储里）：**只有博客这一条路是死的**，备份与药箱不受影响。当前行为 = 永远走"本机仓库 · 线上没够到：<原因>"那条诚实降级。四条出路：

| | 做法 | 代价 |
|---|---|---|
| **D（推荐）** | 在 Cloudflare 把该域的 CA 从 Google Trust Services 换成 **Let's Encrypt**（ISRG Root X1 在 Windows 存储里） | 零代码、零风险，一次控制台点击；证书仍由 Cloudflare 自动续 |
| A | 随包内置 GTS Root R4 作**额外信任锚**，只加给这一个 host | 不放宽校验（是加一条真根），但 CA 一换就再断，维护债在代码里 |
| B | 换 rustls + webpki-roots（Mozilla 根集） | `Cargo.toml` 记着这台机器缺 nasm/cmake，`aws-lc-rs` 编不过；换 `ring` 后端要试，可能把构建拖进坑 |
| C | 接受本机仓库是源，界面明说「可能落后于线上」 | 等于放弃 M10b，回到"拿旧数据当现在" |

## 7. 统计与图表
**选型标准**：每张图必须回答一个能引出动作的问题。个人量级（一天 2–5 项、一年千余条）撑不起 BI 式大屏。

| 图 | 做否 | 回答的问题 / 不做的理由 |
|---|---|---|
| 完成热力图（7×15 周） | 做 | "我有没有连着做" —— 看断点，柱状图看的是形状，替代不了 |
| 每日完成柱状图 | 做 | "哪几天在硬扛"。**必须堆叠区分"按时"与"补做"**，否则只是在数数 |
| 今日构成单值圆环 | 做 | "今天清干净了没"。本质是 gauge 不是 chart，中心放数字、环最多 2 段 |
| 分类投入横向条形 | 做 | "时间花在哪"。比长度准，中文标签可直接写在条上 |
| 建待办时段直方图 | 看数据量 | 洞察强（"晚上建、早上还"），但要 ≥ 30 天才有形状 |
| 多扇形饼图 | 不做 | >3 块不可读；扇形只留给"完成/未完成"二段 |
| 折线趋势 | 不做 | 日粒度噪声大、周粒度点数太少像巧合；≥ 60 天才允许显示 |
| 雷达 / 双轴 / 桑基 | 不做 | 纯装饰。雷达面积不可比，桑基需要个人待办不存在的流转关系 |

**实现：手写 SVG，不引 ECharts / G2。** 图表库压缩后 300 KB+，而上述 5 张图手写约 250 行（热力图 = CSS grid 上色块；柱状图 = flex + 高度；圆环 = `stroke-dasharray`；横条 = div 宽度）。决定性理由是**主题跟随**：手写直接用 `var(--accent)`，切暗色零成本；图表库要喂调色板，其自带 tooltip 还会和我们的浮层打架。与 x-hub"禁止原生 `<select>`"是同一条原则——**外观不受设计令牌控制的元素，在主题化应用里就是债**。

**放置**：独立「统计」视图（侧栏"回顾"分组），不塞进工作台 —— 统计是回顾性的，工作台是行动性的，混起来会让首页变仪表盘。**数据不足时显示空态并写明门槛**（如"需 ≥ 60 天，当前 41 天"），不拿两周噪声画上扬曲线。手机端不做统计页。

**不建 `activity_daily` 物化表**：`done_at` 加索引后按 `date(done_at/86400000)` 分组即毫秒级；提前物化只会引入"统计与列表对不上"这类难查 bug。

### 8.6 反网页感清单（原生质感，逐条进验收）

选 Tauri 之后唯一真实的观感风险就是"看起来像网页"。高级感不来自渲染器（Raycast / Linear / Obsidian / Notion 桌面版全是网页技术），来自下面这些执行细节。**标 M0 的条目是骨架期就要做对的，后补要返工。**

| 会露馅的地方 | 做法 | 定在 |
|---|---|---|
| 系统标题栏 + 原生窗口边框 | `decorations:false` 无边框 + 自绘标题栏，`-webkit-app-region: drag` 划拖拽区，双击最大化 | **M0** |
| 右键弹出浏览器菜单 | 一律用 Tauri `Menu` API 弹真 Win32 原生菜单，禁用默认上下文菜单 | **M0** |
| F12 / 右键检查能开 devtools | 生产构建移除 devtools feature，只在 dev profile 开 | **M0** |
| 多开实例 | `tauri-plugin-single-instance`：已开则聚焦而非新窗 | **M0** |
| 文字随手选中、蓝色高亮 | 全局 `user-select:none`，仅输入区与正文可取 | **M0** |
| 16px 默认字号 + 系统字体 | 13px 基准 + Inter / PingFang SC，数字一律 `tabular-nums` | **M0** |
| 17px 灰色网页滚动条 | 自绘 6px 细滚动条，悬停才显形；内部滚动区各自独立 | M5 |
| 网页式 smooth scroll、大位移动画 | 120–180ms 短促缓动，位移 ≤ 8px；常驻面不做循环动效 | M5 |
| 加载中转 spinner | 原生软件从不转圈：骨架屏或直接不显示 | M5 |
| 文件选择用 HTML `<input type=file>` | 原生文件对话框 + 支持把 exe/lnk 直接拖进窗口（速达的核心交互） | M2 |
| 通知是页面里的 toast | 走 Windows Toast / 通知中心，可点击回跳到具体待办 | M6 |
| 鼠标依赖 | `Ctrl+K` `Esc` `↑↓` `Enter` 全可达 —— 高级感一半来自手不碰鼠标 | M2 |

若这 12 条做完仍觉得"它就是网页"，那时再评估换壳（Flutter 优先于 C++：你药箱已验证 Windows+Android 一套代码、Skia 自绘非 WebView）。但换壳的代价是 x-hub 那 11 万行 Vue 参考代码作废 + mockup 到实现的直通链路断掉，所以**这个评估不该在 M0 之前做**。

### 8.7 侧栏条目（两个候选共用）

侧栏条目由功能清单决定，不由风格决定，所以候选一与候选二内容一致，差别只在宽度（208 / 226px）、分组标题、底部放什么。v1 共 11 项（原 12 项，2026-10-29 合并，理由见下）：

- **（无标题）** 今日驾驶舱 · 待办 `3` · 速达 · 笔记 `42` · **进行中**
- **回顾** — 统计 · 日历
- **外部** — 博客 `6` · 药箱 `2`
- **系统** — 备份 · 设置

> 原来这里是一个「进行」分组，放 倒计时 `2` · 便签 `2` 两条。实测两条都指向同一个视图、只是展开不同的抽屉，于是**同时高亮、点哪条都一样** —— 两个入口做同一件事就是噪声。合并成一条「进行中」，四个部件仍然各自可折叠 / 可隐藏 / 可排序。

底部两张卡：「数据位置 `%LOCALAPPDATA%\dev.rewmington.anvil\app.db · 仅本机`」+「坚果云备份 · 上次成功时间」—— 这是 §2 原则 4「数据位置可感知」的落点。参考图底部的「我的知识库」选择器和「用户卡」不借鉴：那是多人知识库产品的东西，单用户本机应用放用户卡是废的。参考图另外几项（智能分析 / 知识图谱 / 吸收与沉淀 / 扫描记录）一条都不放 —— 没有对应功能，硬凑只会做出"点进去是空页"的导航。

### 8.8 候选一实施要点与风险（M5 按这一节验收）

**1. 3D 卡片环 —— 怎么做才不打架**

- 纯 CSS 3D：容器 `perspective: 1100px`，环 `transform-style: preserve-3d`，6 张卡各自 `rotateY(i*60deg) translateZ(210px)`。不引 three.js、不引动画库。
- 动画**只碰 `transform`**。环及其卡上禁止出现 `filter` / `backdrop-filter` / `box-shadow` 过渡 —— 这三样都触发重绘，正是 x-hub 那个 26% GPU 的来源。
- 巡航 26s 匀速。**三种情况必须真停**：窗口失焦、最小化或收进托盘、用户在设置里开「降低动效」。前两条靠 `visibilitychange` + Tauri 窗口焦点事件驱动，不能只写 CSS `animation-play-state: paused` 就以为停了（标签页隐藏时合成器行为不可依赖）。
- 交互：按住拖动改 `rotateY`、点卡聚焦并同步右栏详情面板、复位视角按钮。**不做惯性滚动、不做物理弹性** —— 那是这类组件里最不值钱的 200 行。
- **降级规则（硬验收）**：可展示卡 < 3 张时不画环，退化成横向卡片列表；0 张时整个部件折叠成一行虚线条（§8.3.3）。不做这条，第一周就会看到一个空转的环。

**2. 照片底 = 预烘焙渐变**

每张 KPI 卡一个 `--glow` 多停点 `radial-gradient`（绿 / 橙 / 蓝 / 粉四组，亮暗主题各一套），零模糊、零额外合成层。截图那种"星云感"主要来自色彩分布而非细节，13px 密度的界面里肉眼差异局限在放大看。

**3. 详情面板（右栏 302px）**

label-value 清单 + 底部 sticky 操作条照抄，字段按本机语义重写：`负责人`→删；`所属目录`→`清单 / 标签`；`首次发现`→`创建 · 来源设备`；新增 `rev` 与 `最后写入设备`（同步字段本来就有，不额外存储）。

**4. 「下一步建议」= 规则引擎，不是 AI**

保留版式，5 条硬规则按优先级取前 3 条：① 逾期最久的一条；② 今天到期且仍未动的最高优先级项；③ 倒计时 < 2 小时；④ 药箱库存 < 2 天（只读源，§6.1）；⑤ 未整理捕获 > 3 条。全部是本地 SQL + 比较，无 LLM、无网络、可单测。规则单独成表维护，改规则不改组件。

**5. 完成时间轴**

月粒度一行日点 + 今天高亮 + 底部完成进度条。**数据 < 60 天不画任何趋势线**，只画点 —— 与 §7「折线趋势 ≥ 60 天才允许显示」是同一条诚实条款。点某天 → 右栏详情面板切到该天明细，复用 §8.1.1 的常驻面板，不另做弹窗。

**6. 密度换来的真代价**

一屏同时有 4 张 KPI + 队列 + 环 + 时间轴 + 详情面板 = 6 个视觉区，比候选二更容易累眼。所以 §2 原则 3「状态不只靠颜色」和 §8.3.1「一屏只允许一个视觉重心」在这一版升级为**硬约束**：选中卡翻亮是唯一的高亮区，其余区一律暗底；**同屏不允许出现两处 `--accent` 实心填充**（这条要在 M5 用截图逐屏检查，不靠自觉）。

**7. 课表网格 —— 什么时候画、什么时候退**

列 = 7 天、行 = 节次，格子里三行（课名 / 教室 / 教师·周次）。硬约束：

- **节次列固定在左**（横向滚动时不跑掉），**今天整列染色**，当前这一节加描边。
- **空档要显式写「空闲」** —— 这张表最有用的一件事就是找空档，留白等于浪费一张网格。
- 1400 宽下内容区 881px、7 列每列约 110px，**长课名必然折行**：允许两行，超出截断 + 悬停看全名。不许为了塞下把字号缩到 11px 以下（§8.6 的 13px 基线）。
- 窄屏（内容宽 < 900px）：右栏收起、网格横向滚动。7 列在 760 宽一定要横滚，这是网格的固有代价，**不做"竖着堆 7 天"那种假响应式**。
- **「此刻」与「选中」必须是两种可视状态**（描边 vs 左色条）—— 真数据上它们会撞在同一个格子里（对比稿上就撞了）。

**8. 待办「今天」档改成有时间的形状**

今天这一屏原来是一条一行，看不出"几点到几点是空的"。改成：一天一横带，**有截止时间的按时间排，没有的落在「随时」**；顶部一行读课表给出「今天 N 节课 · 最近的空档 HH:MM–HH:MM」。

- **课不进这个列表**（§6.7 边界 2），只以那行"空档"摘要出现，且空档与课表页必须由**同一个函数**算出来 —— 两处各写一遍迟早会给出两个答案。
- 其余档（待整理 / 稍后 / 某天 / 已完成）**保持一条一行**：那里没有"今天几点有空"要回答，改成网格只是把清单变难扫。这条是刻意的不统一，别"顺手统一"。

### 8.9 界面文案纪律（M10a，2026-10-30 加）

你说的那句「你这各种位置的说明不就是注释显形吗」是对的，而且能点名：药箱页那段「说实话：坚果云的应用密码是**账号级**的…」、日历底部「灰色格子是别的月份的补位，不是空档」、课表「课表是导入进来的只读副本，改它要回教务导出再导一次」、侧栏底部常驻的 `C:\Users\hp\AppData\Local`。这些写的时候是**说给你我听的实现说明**，不是产品文案 —— 正式软件不会在操作界面上给自己辩护。

三类话，三个去处：

| 类别 | 判据 | 去处 |
|---|---|---|
| **操作提示** | 用户此刻能用上，且不说就会做错 | 留在原地，**每屏最多一句**，≤ 20 字，去掉因果从句 |
| **机制说明** | 回答"它凭什么可信 / 数据在哪 / 什么不出门" | 收进设置页新增的**「关于与隐私」**块（不新增侧栏项：12 项已经是上限，为一个说明页开第 13 项是拿导航换文档） |
| **诊断** | 绝对路径、库文件名、journal_mode | 收进设置页的**「数据与诊断」**（折叠），侧栏底部只留状态一句话 |

两条不能做的：

- **不许删掉真话**。备份页那张「会上传 / 不会上传」表是这软件最值得说清的边界（local-first 的卖点就在这），它只是**不该占主屏** —— 搬家，不是销毁。§2 原则 5（不伪装）与这条不冲突：冲突的是把论证写在按钮旁边。
- **不许换成营销腔**。「你的数据只属于你」这类话比注释更糟：它没有信息量，而且我们做不到绝对（坚果云上有密文）。留下的每句必须**可验证**：说"不进数据库"，就要能打开凭据管理器看到那条。

- ~~备份里能不能带坚果云账号~~ **两条规则要分清（2026-10-30 你回退备份后发现账号密码"消失"）**：`export` 剥掉本机四项（两个邮箱 + 两个绝对路径）是对的，它们不该出门；但 `restore` 是换库不是换机器，所以还原后要把这四项目地写回 —— 名单只有 `MACHINE_LOCAL_KEYS` 一份，剥与留共用它。应用密码从来不进库（只在 Windows 凭据管理器），它没被还原删过，是"邮箱没了 → 没人解释那条密码属于谁 → 表单要求重填"。
